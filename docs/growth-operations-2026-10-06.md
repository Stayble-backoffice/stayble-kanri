対象: https://minpaku.stayble.jp/

## 現状の実測

Google Search Console の URL プロパティ `https://minpaku.stayble.jp/` を確認した。

9月の表示回数は小さく、検索語の公開部分は指名語が中心。`札幌 民泊代行` は5表示・0クリック・平均49位。広い非指名語の獲得は未達である。Search Console では秘匿検索語があるため、公開された検索語の件数を全体の内訳として扱わない。

9月に Gmail の `notify@web3forms.com` から届いた「【乗り換え民泊管理】LPから新規問い合わせ」は確認できなかった。これはフォーム通知の件数であり、電話・直接メール・別経路の相談までゼロと断定するものではない。2026年7月には同フォームの通知を確認できており、送信経路の実績はある。

接続済みのGA4プロパティ4件には9月のホスト別セッションがなかった。サイトのGA4測定タグも現状未設置であり、セッションCVR・離脱・流入経路別CVRは現時点で算出できない。フォーム通知の初回流入情報は、送信された問い合わせの範囲で確認する。

## 今回の判断と実装

1. **フォームの入力負荷を下げる。** 詳細住所・売上・電話番号など9項目必須の構成から、名前・メール・運用状況の3項目だけ必須に変更。住所は市区町村のみ任意。送信直前の確認ダイアログもなくした。低負荷化による問い合わせ増は仮説であり、公開後の通知件数・適合度で判定する。
2. **比較の前提を利用者自身の値にする。** 競合の清掃費や上乗せ額を仮定する積み上げ比較をやめ、月間売上・物件規模・現在の管理費からStaybleの管理費（月額固定費 + 売上5%）と差額だけを概算表示。清掃・リネン等は別途であると計算結果に併記する。
3. **乗り換えの障害を先に説明する。** 既存予約、OTAアカウント、届出、鍵、清掃の切り替えを整理。Airbnbのアカウント間で予約を移行できないという公式説明へリンクし、移行時期の相談につなげる。
4. **登録情報を根拠付きで統一する。** 北海道開発局の2026年9月30日時点の登録簿に、株式会社Stayble・国土交通大臣（01）第F06325号・登録日2026年8月31日が掲載されていることを確認。`BUSINESS.md` を更新し、会社情報ページと `llms.txt` に公的登録簿のリンクを追加。清掃管理の実績は住宅宿泊管理の受託実績として扱わない。
5. **更新日をページ単位にする。** 実際に変えたページだけ `dateModified` と sitemap `lastmod` を2026年10月6日に更新。未変更ページは9月1日を維持する。
6. **地域ページに実務上の違いを加える。** 札幌市内は札幌市、札幌市以外の道内は北海道が住宅宿泊事業の届出窓口であることを公的情報へのリンク付きで明記する。

## 公開後の判定

- Search Console: 非指名語のクリック、トップ・料金・乗り換えページの表示回数とCTR、検索結果で選ばれるページを月次で見る。順位の小さな変動だけで勝敗を決めない。
- 問い合わせ: Web3Forms通知の件数、開業済み物件かどうか、商談・契約への進行、送信時の初回流入情報を確認する。フォームを変えた2026年10月6日を境に比較する。
- GA4: 専用ウェブストリームの測定IDが得られたら、ページ閲覧・フォーム開始・送信成功を実装して、セッションCVRとページ別の離脱を見られるようにする。別サイトの測定IDを流用しない。
- 30日程度の比較では母数が小さいため、1件の増減を施策効果と断定せず、検索流入・有効問い合わせ・商談の方向を合わせて評価する。
